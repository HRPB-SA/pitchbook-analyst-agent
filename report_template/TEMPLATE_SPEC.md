# Report templates

A template JSON declares the report's contract: section order, what each
section must contain, which sections are auto-generated from the store, chart
expectations, cover furniture, and which gates fire before ship. The composing
agent fills prose sections in the house voice (style/STYLE.md +
style/style_profile.json); `auto` sections are generated by
`engine.compose` so every report carries a verified data backbone.

## Template fields

```
id, name, kicker            identity; kicker prints on the cover
length_pages                target band; the dial for depth
rigor                       1-5; drives validation depth per the kernel
outname_pattern             e.g. "{company}_Update_{monyyyy}"
cover                       hero_tiles guidance (3 tiles), snapshot: true/false
sections[]                  ordered; each has:
    id, title_hint          title_hint shows the expected titling pattern
    required[]              content obligations, checked at review
    auto                    "tracker" | "fact_sheet:<cats>" | null
    charts[]                chart-type suggestions from the house factory
toc                         contents page yes/no
gates[]                     "report_ship" fires Protocol 2's full gate
```

## Section obligations are binding

`required` entries are the editorial contract. The reviewer (agent or human)
checks each one; an unmet obligation is an unshipped report, per the
no-TODOs cardinal rule.

## Choosing a template

- vertical_analyst_note   THE DEFAULT: the analyst-provided master template
                          (production metadata sheet + key takeaways +
                          sections + references; `analyst_note` theme)
- initiation_note   first full coverage of a company (30+ pages)
- company_update    coverage refresh when the tracker shows material change
- rush_note         one event, shipped fast (4-8 pages)
- earnings_note     a dated print: expectations vs actuals vs thesis
- one_pager         single page; the fact sheet + verdict only
- sector_overview   a sector pass using the 12-point industry frame

A dashboard request may also specify `custom` with its own section list; the
engine renders whatever sections it is given, so custom shapes need no code.
